# Rust 0.5.0 and Python 0.1.0a2

Prepared release versions; publication requires merging the reviewed change and
publishing GitHub releases `v0.5.0` and `python-v0.1.0a2` from that main commit.
The Python release remains an alpha. These are independent package versions;
the frozen protocol 1.0 and its conformance artifacts are unchanged.

## Rust workspace

All eighteen public crates advance together from 0.4.1 to 0.5.0 for the added
host/guest integration, typed numeric capabilities, quantized authoring helpers,
and backend APIs accumulated since the previous release. The stack includes
vhost-user/QEMU integration, the Linux guest path, backend benchmarks with
configurable in-flight depth, FP8 activation/storage paths, runtime NVFP4
projections, OpenVINO compressed integer weights and Core ML compressed
integer/palette weights. MSRV, portable defaults and platform boundaries remain
unchanged. Backend support is tier-specific, not uniform across all devices.

Core ML and OpenVINO integer MATMUL now reject worst-case absolute sums above 2**24:
native compilers can lower their INT32 operation through FP32 arithmetic. This admission
restriction prevents silently rounded results; for zero zero-points K <= 1024.
Singleton-batch OpenVINO lookups lower to equivalent unbatched Gather operations,
avoiding CPU-plugin corruption/crashes for short NVFP4 block-scale tensors.
Pure FP8 storage graphs use byte carriers to preserve NaN payloads on the GPU.
No fallback or floating reinterpretation of an integer result is introduced.

## Python SDK

Adds FP8 E4M3FN/E5M2 and INT8/INT32 storage, explicit permitted casts, integer
MATMUL, and composable `virtio_accel.quantized` INT4/INT8/palette/NVFP4 helpers.
The immutable constant, explicit device, bounded graph, reusable-buffer and
no-implicit-fallback contracts remain intact. The Linux guest adapter sizes
bindings from dtype metadata, including one-byte FP8/INT8 and four-byte INT32.
Generated API documentation covers the new exports and includes an executable
packed-weight example. See the Python guide for format and admission limits.

The first-release wheel matrix remains unchanged. Windows ARM64/Hexagon wheels
are deferred (issue #209); Hexagon source builds remain available. Creating a
TestPyPI project is optional and is not a production publication prerequisite.
