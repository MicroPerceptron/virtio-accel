# virtio-accel.org website

This module builds and deploys the public site for `virtio-accel.org`. It is
deliberately **not** a Cargo workspace member: it is a Python + mdBook project,
so it stays out of `cargo fmt --all`, `cargo clippy --workspace`, and
`cargo doc --workspace` and never affects the crate release pipeline.

## Layout

| Path | Purpose |
| --- | --- |
| `book.toml` | mdBook configuration (pinned to mdBook 0.5.x) |
| `build.py` | Single build entry point: curates docs, rewrites links, generates `SUMMARY.md`, builds rustdoc + mdBook |
| `content/` | Hand-authored pages (`index.md` landing, `api.md` reference index) |
| `theme/` | Custom favicon, color variables, and landing-page CSS |
| `src/` | Generated by `build.py`; git-ignored |
| `book/` | Generated site output; git-ignored |

## Local build

Requires Rust (1.85+) and mdBook 0.5.x:

```sh
cargo install mdbook --version 0.5.4 --locked
python3 website/build.py
```

The finished site is in `website/book/`. Serve it locally with any static file
server, e.g. `python3 -m http.server -d website/book 8000`.

`build.py` accepts `--skip-rustdoc` and `--skip-mdbook` to iterate on one half
of the pipeline.

## What gets published

- The curated narrative docs under `docs/` (specification, wire ABI, virtqueue,
  architecture, threat model, portability, performance, public API, release
  policy, backend guide, Hexagon matrix, and the 1.0 release notes).
- The repository `README.md` as "Getting started".
- rustdoc for the whole workspace (`cargo doc --workspace --all-features
  --no-deps`) under `/api/`.

The internal `docs/agents/` and `docs/plans/` trees are **excluded**. Links from
curated docs to repository files that are not part of the site (source files,
`include/virtio_accel.h`, conformance artifacts, licenses) are rewritten to
point at GitHub.

## CI/CD

`.github/workflows/website.yml` rebuilds and deploys the site:

- on every push to `main`, and
- after a successful `Publish crates` run (via `workflow_run`), so a new
  release refreshes the rustdoc automatically.

The build job runs `python3 website/build.py` and uploads `website/book/` as an
artifact. The deploy job downloads it and rsyncs it to the droplet over SSH.

## DigitalOcean droplet setup

Create a droplet (any size; a 1 GB basic droplet is plenty for a static site)
running a recent Debian or Ubuntu image, then:

```sh
# On the droplet, as root:
apt-get update && apt-get install -y nginx rsync
mkdir -p /var/www/virtio-accel.org
chown -R www-data:www-data /var/www/virtio-accel.org

# Create a dedicated deploy user with an SSH key:
adduser --disabled-password --gecos "" deploy
mkdir -p /home/deploy/.ssh
# Paste the deploy public key into /home/deploy/.ssh/authorized_keys
chmod 700 /home/deploy/.ssh && chmod 600 /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
```

An nginx server block that serves the static tree:

```nginx
server {
    listen 80;
    server_name virtio-accel.org www.virtio-accel.org;

    root /var/www/virtio-accel.org;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

Enable it with `ln -s /etc/nginx/sites-available/virtio-accel.org
/etc/nginx/sites-enabled/` and `systemctl reload nginx`. TLS is left to your
preference (e.g. `certbot --nginx`).

## Required repository secrets

The deploy job reads these GitHub Actions secrets:

| Secret | Description |
| --- | --- |
| `DO_DEPLOY_SSH_KEY` | Private key for the `deploy` user on the droplet (no passphrase) |
| `DO_DEPLOY_HOST` | Droplet IP address or hostname |
| `DO_DEPLOY_USER` | SSH user, e.g. `deploy` |
| `DO_DEPLOY_PORT` | SSH port, e.g. `22` |
| `DO_DEPLOY_PATH` | Absolute target directory, e.g. `/var/www/virtio-accel.org` |

Set them under **Settings → Secrets and variables → Actions**. The deploy job
uses `rsync` with `--delete` so the remote tree exactly mirrors the build.
